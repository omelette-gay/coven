# Object Store

Installs a single-node RustFS S3-compatible object store and creates the requested buckets. Bucket creation uses
the [`rustfs/rc`](https://hub.docker.com/r/rustfs/rc) CLI; its version is pinned in `locals.tf` and kept up to date
by Renovate.

The access and secret keys are generated by the [generated-secret](../generated-secret/) module, so they're kept in
Vault (`object-store/<namespace>/<name>`) and synced into the `<name>-object-store-keys` Secret by External Secrets
Operator, and aren't in Terraform state.

## Versioning

Buckets in `versioned_buckets` have versioning turned on, so overwriting or deleting an object keeps its old versions.
Grist needs this for its document history. Taking a bucket out of the list doesn't turn versioning off.

## Public S3 API

By default RustFS is only reachable inside the cluster. Some apps, such as Outline, have users upload and download
directly with presigned URLs, so their browsers need to reach it. `public_api` serves the S3 API on a public hostname
for those buckets:

```hcl
public_api = {
  host                 = "docs-files.omelette.gay"
  cluster_issuer       = "letsencrypt"
  buckets              = ["outline"]
  cors_allowed_origins = ["https://docs.omelette.gay"]
}
```

- **Only the listed buckets are routed**, as `https://<host>/<bucket>/...` (path-style). The S3 port also serves
  RustFS's admin API under `/rustfs/`, which takes the same root keys the apps use, so the Ingress allows bucket paths
  rather than blocking admin ones. Other buckets, the admin API and the health checks get Traefik's 404. The console
  (port 9001) is never exposed.
- **The buckets stay private.** Every request still needs a signature, so only presigned URLs work. The app has to
  presign against the `public_endpoint` output rather than `endpoint`, as the signature covers the host.
- **CORS rules** are set on the listed buckets, allowing `GET`, `HEAD`, `PUT` and `POST` from `cors_allowed_origins`.
  RustFS only sends CORS headers for buckets with rules, so other origins are refused. Taking a bucket out of the list,
  or removing `public_api`, removes its route but not its CORS rules.
- The app holds RustFS's root keys, as with any store from this module. They can't reach the admin API from outside,
  but they can still use it from inside the cluster.

## Backups

RustFS keeps its data on a single Longhorn volume. Set `longhorn_recurring_job_name` (e.g. `nightly-backup`) to back
it up off-site: the module then creates the volume itself, labelled for that Longhorn recurring job, and points the
chart at it. Without it, the chart creates an unlabelled volume that isn't backed up, which is fine for data that can
be lost (like GlitchTip's). Set it when the store is first created: changing it later switches RustFS to a new, empty volume.

## Telemetry

Every store sends metrics to Prometheus's OTLP receiver, labelled `job="<namespace>/<name>-rustfs"`, and logs to
stdout, where Alloy collects them into Loki. Traces and OTLP logs are turned off, as Prometheus only accepts metrics
(see [#93](https://github.com/omelette-gay/coven/issues/93) for tracing).
